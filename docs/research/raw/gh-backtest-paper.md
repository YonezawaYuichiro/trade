## 結論(5〜10 行)

1. 「寄り成行で入り、引け成行で出る」日次シミュレーションは **自作 40〜60 行(pandas)で足りる。エンジンは不要**。日足 1 本の中で O→C の往復を表現する設計になっている汎用エンジンは少なく(backtesting.py は「次バー始値」か「当バー終値」の二択、vectorbt の `from_signals` は 1 バー 1 注文)、無理に載せるとバーを 2 分割する小細工が要る。本ノート末尾に動作確認済みの最小コードを置いた。
2. 東証の寄成・引成は **板寄せ(単一価格)で約定する**ため、小口なら約定価格は「始値そのもの」「終値そのもの」で、ザラバのようなビッド・アスクスプレッドは払わない(JPX 規則で確認)。現実的に入れるべきは (a) 不約定(ストップ配分・寄らず)、(b) 特別気配による寄り時刻の遅延、(c) 感度分析用の安全マージン(片道 0.5 tick または 5bps)。手数料は主要ネット証券で 0 円化済み(SBI ゼロ革命ほか)。
3. 日本株を **API で自動売買できる無料の公式ペーパートレード環境は確認できなかった**。kabuステーションAPI の「検証用」(18081)は固定/空レスポンスで約定を模擬しない(公式コミュニティ issue #451/#377)。moomoo OpenAPI は日本株の Paper Trading 非対応(公式 doc の対応表で X)。GUI 手動なら moomoo デモ取引が日本株対応(仮想 2,000 万円)。立花証券 e支店 API のデモ環境は存在するが詳細は未確認。
4. したがって MVP は「予測を寄り前に追記専用で記録 → 16:30 以降に確定日足で自前採点」。先行実装として **yuichiro-yokote/quant-jp**(日本株 1 年ペーパートレード、ハッシュチェーン日誌、事前登録の合格基準)と **YutaroSugaya/stock-bot**(day-block bootstrap、Šidák 補正、ホールドアウト 1 回焼き、の検定規律)がそのまま設計の手本になる。
5. エンジンの生死: backtrader は実質停止(PyPI 最終 2023-04、push 2024-08)。backtesting.py 0.6.6(2026-07)、vectorbt 1.1.2(2026-10-09)、bt 1.4.1(2026-10-10)、nautilus_trader 1.231.0(2026-08)、zipline-reloaded 3.1.1(2025-07、リポジトリは 2026-10-13 push)は生存。すべて Windows・Python 3.13 用ホイールあり(backtrader は未確認)。
6. 鮮度の高い制度変更 2 件: **2027-03-01 から呼値の単位が TOPIX500 区分 → 銘柄別流動性(STR)ベースの A/B/C テーブルへ**、**2027-10-12 から大引けにランダムクローズ導入**。コストモデルと「引け」の定義は日付依存で持つ必要がある。
7. 既存エンジンは「照合用」と割り切る: 自作結果を vectorbt で突合(quant-jp が実践、861.55% 対 849.49% で約定回数一致)、レポートは quantstats、カレンダーは exchange_calendars(XTKS、2024-11-05 以降 15:30 引け反映済み)。

## 詳細(項目ごとに、中身・数値・使い方・限界)

### A. 必須の 4 問への回答

#### (1) 「寄り成行で入り引け成行で出る」日次シミュレーションの最小構成

結論: **自作で足りる。エンジンは要らない。**

理由(各エンジンの約定規則を公式 doc で確認した結果):

| エンジン | 日足 1 本での O→C 同日往復 | 根拠 |
|---|---|---|
| backtesting.py 0.6.6 | 直接は不可。成行は「次バーの始値」、`trade_on_close=True` で「当バーの終値」。どちらも 1 バー内で建てて閉じる表現にならない | 公式 API doc ✅。回避策(1 日を寄りバー・引けバーの 2 行に展開)は自分の案で未検証 |
| vectorbt 1.1.2 | `from_signals` は `price=Open` で始値約定にできるが 1 バー 1 注文。同一バー複数注文は `from_order_func(flexible=True)`(`flex_simulate_nb`) | 公式 doc ✅(同日往復の公式例は見つからず) |
| backtrader | `Cerebro(cheat_on_open=True)` + `next_open()` で当日始値約定は公式例あり。`Order.Close` は「次バーの終値」と記載。`next_open` 内で出した `Order.Close` が当日終値になるかは未確認 | 公式 doc ✅ / 同日決済は ❓ |
| LEAN | `MarketOnOpen` は公式の寄り付きオークション価格で約定、寄りの 2 分以上前に発注。ただし doc の対象は US Equity。日本株データは標準提供を確認できず(doc で確認できた Equity の Market は `Market.USA` のみ) | 公式 doc ✅ / 日本株は ❓ |
| nautilus_trader | 日足 Bar ベースのサンプルは 15:30 タイムスタンプで 1 バー 1 イベント。O と C を別イベントにするには Bar を分割する必要がある(推測) | サンプルコード ✅ / 分割要否は推測 |

O→C の損益は `side × (C/O − 1) − コスト` の 1 行で書ける。エンジンが価値を持つのは「資金制約つき複数銘柄の配分」「指値・逆指値のザラバ判定」「ポジションの持ち越し」が入ってから。quant-jp も複数銘柄部分は自作(`backtest/portfolio.py` 約 230 行)で、vectorbt は照合用に限定している。

自作で最低限入れるもの(詳細 G にコード):

1. 約定判定: 始値あり・出来高 > 0・寄りがストップ高(買い)/ストップ安(売り)でない。
2. コスト: 手数料 bps + 片道 tick 数 × 呼値 / 始値(往復で 2 倍)。
3. 的中: `sign(C − O) == side`。
4. 集計: 日次平均 net、日単位ブロックのブートストラップ CI。
5. 記録の改ざん防止: 予測 JSON にハッシュチェーン + git コミット。

#### (2) 日本株の寄り/引けの約定・コストを現実的に入れる方法と既存実装

制度面(JPX 一次情報、詳細 E):

- 寄り(9:00、後場は 12:30)と大引け(15:30)は板寄せ。売り買いが合致する単一の値段で全量が約定する。成行は指値に優先する。つまり **寄成・引成の約定価格は公表される始値・終値と一致**し、ザラバ成行のようにスプレッドの半分を払う構造ではない。
- 2024-11-05 以降、15:25〜15:30 はプレ・クロージング(注文受付のみ)、15:30 にクロージング・オークション。引条件付注文・不成注文は 15:25 に板へ取り込まれる。大引けで成立する値幅はザラバ最終値段の更新値幅の 2 倍まで。
- 不約定・想定外になる場面: (a) 特別気配で 9:00 に寄らない(3 分ごとに更新値幅ずつ移動)、(b) ストップ高/安でのストップ配分(成行は制限値段の指値とみなされ、証券会社単位で比例配分。もらえないことがある)、(c) 大引けで売買不成立。

手数料面:

- SBI 証券「ゼロ革命」: インターネットコース + 各種書面の電子交付で、現物・信用・S株の売買手数料が約定金額にかかわらず無料(公式 LP ✅。開始日 2023-09-30 約定分からは検索要約 ❓)。
- 楽天証券「ゼロコース」: 2023-10 から無料(検索要約 ❓)。
- 信用の日計り: 楽天「いちにち信用」は 2022-03-14 約定分から金利・貸株料 0%(公式告知 ✅、ただし 2022 年の告知で現況は未確認)。当日中に返済しないと翌営業日に強制決済 + 手数料。特別空売り銘柄は特別空売り料が別途。SBI「日計り信用」は当日返済で 0%、持ち越すと年 1.80%(検索要約 ❓)。
- 結論: デイトレ(O→C)の明示コストは「手数料 0・金利 0」を基準ケースにしてよい。空売り側は特別空売り料と在庫の有無が別リスク。

### B. 日本株特化の先行実装(掘り当てたもの)

#### B-1. yuichiro-yokote/quant-jp(本プロジェクトに最も近い)

- 目的: 日本株(日足)で架空資金の 1 年フォワードテスト。2026-08-15 に目的を定義し直し、「1 年で分かるのは仕組みが正しく動くか・記録が改ざんされていないか・シミュレータが現実を再現するか・破滅的損失を出さないか」「1 年では分からないのは戦略が市場に勝てるか」と整理。
- 戦略: 月末に 12-1 モメンタム上位 5 銘柄を等ウェイト、翌営業日寄付で執行。資金 10 万円、SBI の S株(1 株単位)前提、成行のみ。
- データ: yfinance を主、J-Quants Free(約 12 週遅延)を検算。yfinance は上場廃止銘柄を返さない(実測: 期首 3,800 銘柄の 6.7% = 256 銘柄が廃止。廃止銘柄の平均リターン +34.5%、全体への歪みは −0.40 ポイント)。
- 記録: `paper/journal/` に 1 営業日 1 JSON。フィールドは `date, generated_at, git_commit, prev_hash, universe, fills, positions, cash, equity, signal, notes, hash`。ハッシュは `hash` を除いた本体を `json.dumps(sort_keys=True, ensure_ascii=False, separators=(",", ":"))` で直列化して SHA-256。初日は `"0"*64`。`verify()` はファイル名と date の一致・prev_hash の連結・hash の再計算の 3 点を検査。限界: ある日以降を丸ごと再計算して書き換えられると検出不能(git 履歴が外部の証人)。
- 合格基準(`CRITERIA.md` 第 2 版、2026-08-15、フォワード開始前に確定): A1 ハートビート欠測 5 営業日以下 / A2 日誌の手編集 0 件 / A3 年 30 取引以上 / A4 シミュレータと実記録の乖離を説明できること / A5 中断条件に触れず 1 年完走。B 最大ドローダウン 30% で即中断。E データ欠損・実行失敗が 10 営業日連続で停止。F「バックテストで負けた結果は採用、勝った結果は採用しない、合格判定はフォワードのみ」。開始後は文書を変更しない。
- 報告されている数値: シミュレータと記録の乖離は 90 営業日・41 約定で 0.0000%。実力ゼロでも保有 10 銘柄なら 1 年で標準偏差 14.2%、ランダム 5 銘柄の超過リターン標準偏差 20.0%。5 銘柄で年 3% の実力を証明するには 178 年(自前の検定力分析 `research/power.py`)。フォワードの損益は README に未掲載。
- ライブラリ選定: backtesting.py(1 銘柄)、自作(複数銘柄)、vectorbt(照合のみ)、quantstats(レポート)。不採用は backtrader(開発停止)、zipline-reloaded(停滞)、bt(Windows のインストール問題)、pyfolio(非推奨)。

### G. 自作最小構成(合成データで実行確認済み: Python 3.13.5 / pandas 3.0.3 / numpy 2.3.1)

入力:

- `bars`: 索引 (date, code)、列 `prev_close, O, C, Vo, topix500`(J-Quants の O・C・Vo と前日 C、TOPIX500 所属フラグ)。
- `preds`: 索引 (date, code)、列 `side`(+1 買い / −1 売り / 0 見送り)。

```python
import hashlib, json, math
import numpy as np, pandas as pd

# 東証の制度テーブル(JPX「内国株の売買制度」2026-10-13 閲覧。2027-03-01 に呼値は STR ベースへ変更)
_TICK_BOUNDS = [1000, 3000, 5000, 10000, 30000, 50000, 100000, 300000, 500000, 1e6, 3e6, 5e6, 1e7, 3e7, 5e7, float("inf")]
_TICK_T500 = [0.1, 0.5, 1, 1, 5, 10, 10, 50, 100, 100, 500, 1000, 1000, 5000, 10000, 10000]
_TICK_OTHER = [1, 1, 5, 10, 10, 50, 100, 100, 500, 1000, 1000, 5000, 10000, 10000, 50000, 100000]
_LIMIT = [(100, 30), (200, 50), (500, 80), (700, 100), (1000, 150), (1500, 300), (2000, 400), (3000, 500),
          (5000, 700), (7000, 1000), (10000, 1500), (15000, 3000), (20000, 4000), (30000, 5000), (50000, 7000),
          (70000, 10000), (100000, 15000), (150000, 30000), (200000, 40000), (300000, 50000), (500000, 70000)]
_RENEW = [(200, 5), (500, 8), (700, 10), (1000, 15), (1500, 30), (2000, 40), (3000, 50), (5000, 70),
          (7000, 100), (10000, 150), (15000, 300), (20000, 400), (30000, 500), (50000, 700), (70000, 1000),
          (100000, 1500), (150000, 3000), (200000, 4000), (300000, 5000), (500000, 7000)]

def tick_size(price, topix500):
    for bound, t500, other in zip(_TICK_BOUNDS, _TICK_T500, _TICK_OTHER):
        if price <= bound:
            return t500 if topix500 else other

def _lookup(table, base):
    for upper, width in table:
        if base < upper:
            return width
    raise ValueError("50 万円以上は表を拡張すること")

def price_limits(prev_close):
    """(ストップ安, ストップ高)。制限値幅の臨時拡大は考慮しない。"""
    w = _lookup(_LIMIT, prev_close)
    return prev_close - w, prev_close + w

def est_open_delay_min(prev_close, indicative_open):
    """特別気配で寄りが何分遅れるかの目安(3 分ごとに更新値幅ずつ移動)。"""
    w = _lookup(_RENEW, prev_close)
    return 3 * max(0, math.ceil(abs(indicative_open - prev_close) / w) - 1)

def score_open_to_close(bars, preds, *, fee_bps_oneway=0.0, slip_ticks_oneway=0.0):
    j = preds.join(bars, how="left")
    lim = [price_limits(p) if pd.notna(p) else (np.nan, np.nan) for p in j["prev_close"]]
    lo = np.array([x[0] for x in lim]); hi = np.array([x[1] for x in lim])
    tick = np.array([tick_size(o, t) if pd.notna(o) else np.nan for o, t in zip(j["O"], j["topix500"])])
    filled = j["O"].notna() & (j["Vo"] > 0) & (j["side"] != 0)
    # ストップ高寄りの買い・ストップ安寄りの売りは比例配分で約定しない前提(保守側)
    filled &= ~((j["side"] > 0) & (j["O"] >= hi)) & ~((j["side"] < 0) & (j["O"] <= lo))
    # 手仕舞い側がストップに張り付いた日は「引けで出られなかった可能性」として旗を立てる
    exit_ok = ~((j["side"] > 0) & (j["C"] <= lo)) & ~((j["side"] < 0) & (j["C"] >= hi))
    gross = j["side"] * (j["C"] / j["O"] - 1.0)
    cost = 2.0 * (fee_bps_oneway / 1e4 + slip_ticks_oneway * tick / j["O"])
    j["filled"] = filled
    j["exit_at_limit"] = filled & ~exit_ok
    j["net"] = np.where(filled, gross - cost, np.nan)
    j["hit"] = np.where(filled, np.sign(j["C"] - j["O"]) == np.sign(j["side"]), np.nan)
    daily = j.groupby(level="date")["net"].mean()      # 日次の等ウェイト平均
    return j, daily

def day_block_ci(daily, n=10000, alpha=0.05, seed=0):
    """日単位ブロックのブートストラップ(同じ日の銘柄は相関するのでトレード単位にしない)。"""
    x = daily.dropna().to_numpy()
    rng = np.random.default_rng(seed)
    means = rng.choice(x, size=(n, len(x)), replace=True).mean(axis=1)
    lo, hi = np.quantile(means, [alpha / 2, 1 - alpha / 2])
    return float(x.mean()), float(lo), float(hi)

def chain_hash(entry, prev_hash):
    """予測記録の改ざん検出。初日は prev_hash = '0' * 64。"""
    body = dict(entry, prev_hash=prev_hash)
    blob = json.dumps(body, sort_keys=True, ensure_ascii=False, separators=(",", ":"))
    return hashlib.sha256(blob.encode("utf-8")).hexdigest()
```

このコードが扱わないもの(意図的に省略): 資金制約と 100 株単位の配分、ザラバ中の損切り(H/L を使う判定)、制限値幅の臨時拡大、2027-03 以降の呼値、空売りの可否(貸借・在庫・空売り価格規制)、税金。

### H. 検証方法論(先行実装から拾える規律)

- 予測は寄り前に確定させ、追記専用で残す。ハッシュチェーンだけでは「全部書き直し」を防げないので、git の履歴(できればリモート)を外部の証人にする(quant-jp)。
- 判定基準は開始前に文書化し、開始後は変えない。緩めたくなったら検証の価値は失われる(quant-jp `CRITERIA.md`)。
- バックテストで勝った結果は証拠にしない。負けた結果は採用する(quant-jp F)。
- CI は日単位で取る。銘柄横断のトレードは市場全体の下落日に固まるので、トレード単位だと CI が狭くなりすぎる(stock-bot)。
- 試した数だけ有意水準を割る(Šidák)。グリッドの最良セルを結論にしない。仮説とその真逆が両方通ったら両方捨てる(stock-bot)。
- ホールドアウトは 1 回しか見ない。覗いたら焼いたことにする(stock-bot)。
- LLM を判断に使うなら同じ入力で複数回回し、ぶれを記録する(ai-trade-check で ±7%)。「問い」の文言を変えたら版を上げ、版をまたいで件数を合算しない(jev-forward)。

## 因果ルール候補

本観点は基盤調査のため、値動きの統計的アノマリーではなく「約定とコストを決める制度上の因果」と「検証結果の読み方に関する経験則」が中心。確度の「制度」は取引所規則で機械的に決まるもの(統計研究ではないので A/B/C の外。予測精度ではなく約定可否の判定に使う)。

### R1. 特別気配による寄り遅延

- IF 寄り前の合致値段 P* と基準値段 P0(前日終値)の差が更新値幅 w を超える → THEN 9:00 には寄らず特別気配。気配は 3 分ごとに w ずつ P* 側へ動き、寄り時刻の目安は 9:00 + 3 分 × (ceil(|P* − P0| / w) − 1)。例: P0 = 1,000 円(w = 30 円)、P* = 1,100 円なら 9:09 頃。
- なぜ: 直前価格から更新値幅を超える約定を即時に成立させず、反対注文を呼び込む制度。
- 根拠: JPX「売買成立の方法」「特別気配の更新値幅」 https://www.jpx.co.jp/equities/trading/domestic/04.html / 05.html(寄り時刻の式は規則からの自分の導出)。
- 効かなくなる条件: 途中で反対注文が入れば早く寄る。価格帯をまたぐと w が変わる。制限値幅に達すればストップ気配で寄らない。
- 必要データと入手時刻: 寄り前気配(8:00〜9:00、板情報。証券ツールや BRiSK)。日足だけでは寄り時刻は分からない(分足アドオンが必要)。
- 確度: 制度(規則で確定)。式の実測検証は未実施。

### R2. ストップ配分による不約定

- IF 寄りまたは引けがストップ高(安)で決まる → THEN 成行買い(売り)は制限値段の指値扱いで比例配分となり、全量約定を仮定できない。バックテスト・採点では不約定または除外にする。
- なぜ: 需給が偏り成行を全量約定できないため、通常の板寄せ規則を適用しない。配分は証券会社単位、顧客への配分は各社ルール。
- 根拠: JPX「売買成立の方法」ストップ配分の項。
- 効かなくなる条件: 制限値段に十分な反対注文があれば通常どおり寄る(O = 制限値段でも全量約定はあり得る)。保守側に倒す前提。
- 必要データ: 前日終値(制限値段の計算)、当日 O・C。J-Quants の UL/LL は「高値(安値)が到達したか」なので寄り・引けの判定には不足。16:30 頃。
- 確度: 制度。

### R3. 制限値幅の拡大

- IF 2 営業日連続で「ストップ高(安)・配分なし・売買高 0」または「売買高 0 のまま引け、引けでのみストップ成立・残数あり」 → THEN 翌営業日から制限値幅が拡大される。
- なぜ: 値がつかない状態を解消するための臨時措置。
- 根拠: JPX「制限値幅」 https://www.jpx.co.jp/equities/trading/domestic/06.html(2026-10-09 更新)。拡大幅はこのページに記載なし(未確認)。
- 効かなくなる条件: 重複上場外国銘柄は対象外。ETF 等は別ルール(ストップで立会終了なら翌日から拡大)。
- 必要データ: 日足の O/H/L/C/Vo とストップ情報(JPX が該当銘柄を日々公表)。
- 確度: 制度。

### R4. 最小スプレッドは呼値 ÷ 株価で決まる

- IF 銘柄が「その他」テーブルで株価が低い(例 200〜500 円) → THEN ザラバ成行の往復コスト下限は 20〜50bps。TOPIX500 なら同じ株価で 2〜5bps。板寄せ(寄成・引成)で出入りすればこのコストは発生しない。
- なぜ: 気配は呼値の刻みより細かく出せないため、スプレッドは最低 1 tick。
- 根拠: JPX「呼値の単位」 https://www.jpx.co.jp/equities/trading/domestic/07.html(bps は自分の計算)。
- 効かなくなる条件: 実際のスプレッドが 2 tick 以上の低流動性銘柄ではさらに高い。2027-03-01 以降は STR ベースの A/B/C テーブルに変わる。
- 必要データ: 株価、TOPIX500 所属(2027-03 以降は適用テーブル)。前日までに確定。
- 確度: 制度(下限値として)。

### R5. 呼値を細かくするとスプレッドが縮む

- IF 取引所が呼値の単位を縮小する → THEN ビッド・アスクスプレッドは縮小、最良気配のデプスは減少。2023-06-05 の TOPIX Mid400 では東証のスプレッドが約半分になり、対象銘柄の PTS 出来高は 50% 以上減った。
- なぜ: 従来はスプレッドが呼値に張り付いていた(STR が 1 に近い)ため、刻みを細かくすると競争で縮む。
- 根拠: 宇野淳・戸辺玲子(2025-03-25)「日本株式市場における市場間競争とティックサイズ」SBI 金融経済研究所 https://sbiferi.co.jp/report/20250325_1.html ✅。JPX ワーキング・ペーパー Vol.42(若松弘晃、2024-01-31)は、呼値 80%・90% 減のグループで気配スプレッドが有意に減少、最良気配付近の累積デプスが約 10〜13% 減と報告(検索要約のみ、本文未確認 ❓)。Vol.40(2022)の事前試算は実効スプレッド約 39% 減。
- 効かなくなる条件: 50% 減のグループでは有意でなかった(Vol.42、❓)。もともとスプレッドが 2 tick 以上の銘柄では効果が薄い可能性。
- 必要データ: 制度変更日と対象銘柄一覧。事前に公表される。
- 確度: B(レポート 1 本を確認、JPX WP は未確認)。値動き予測ではなくコスト水準の予測。

### R6. インパクトは注文量の平方根に比例

- IF 自分の注文量 Q が市場の出来高に対して無視できない → THEN 価格インパクトは Q^(1/2) に比例して増える。
- なぜ: 潜在的な流動性の構造に由来するとされる経験則(メカニズムは論文間で議論あり)。
- 根拠: Sato & Kanazawa, Phys. Rev. Lett. 135, 257401 (2025)、arXiv:2411.13965。東証の全流動銘柄・全取引口座・8 年。指数 δ は銘柄別・トレーダー別とも統計誤差内で 1/2。係数の値は abstract に無く未確認。
- 効かなくなる条件: 対象はザラバのメタオーダー。板寄せでの成立は対象外。
- 必要データ: 日次出来高、日次ボラティリティ。
- 確度: A(平方根則自体は多数の市場で再現されており、本論文は東証全数データでの確認)。ただし 100 株単位の個人の予測採点には実質影響しない。

### R7. 大引けの成立値幅

- IF 大引けの板寄せで合致値段がザラバ最終値段から更新値幅の 2 倍を超える → THEN 通常の板寄せでは成立せず、特別約定の条件(上限・下限値段に売り買い各 1 単位以上)を満たせばその値段で成立。満たさなければ引成は約定しない。
- なぜ: 引けでの過度な価格変動を抑える制度。
- 根拠: JPX「売買成立の方法」クロージング・オークション、特別約定の項。
- 効かなくなる条件: 2027-10-12 からランダムクローズ導入で板寄せ時刻が変わる(値幅規則の変更有無は未確認)。
- 必要データ: 15:25 時点の最終値段、プレ・クロージングの気配。日足では終値の有無と出来高で事後判定。
- 確度: 制度。

### R8. ペーパーの黒字は期間を伸ばすと消える(経験則)

- IF ペーパートレードの黒字が特定期間と少数銘柄に依存している → THEN 期間を伸ばすとコスト込みのエッジは消える可能性が高い。
- なぜ: 少数の当たりトレードへの過適合、レジーム依存。
- 根拠: YutaroSugaya/stock-bot README(日本株、25 日線乖離逆張り・ブレイクアウト・モメンタム。数値は非公開)。
- 効かなくなる条件: 事前登録済みで、3 レジーム中 2 以上で net 正、ベンチ超過の CI 下限 > 0 を満たす場合は別。
- 必要データ: 自分のフォワード台帳。
- 確度: C(個人 1 例、数値なし)。

### R9. 1 年のフォワードでは銘柄選択の実力は証明できない(検定力)

- IF 保有 5 銘柄・年単位の評価 → THEN 実力ゼロでも超過リターンの標準偏差は約 20%(10 銘柄で 14.2%)。年 3% の実力の証明には 178 年かかる。
- なぜ: 個別株リターンの分散が大きく、独立な試行数が少ない。
- 根拠: yuichiro-yokote/quant-jp README(`research/power.py` による自前シミュレーション、日本株)。
- 効かなくなる条件: 毎日多数の銘柄に O→C 予測を出す設計なら試行日数が年 245 前後、銘柄数も多く、検定力は大きく上がる(ただし同日の銘柄間相関があるので日単位で数える)。
- 必要データ: 自分の予測台帳。
- 確度: C(単独の自前分析。方向性は統計の一般論と整合)。

### R10. LLM 判断は同じ入力でも結果がぶれる

- IF 売買判断を LLM に任せる → THEN 同じ設定でも実行ごとに累積リターンが ±7% 程度ぶれる。
- なぜ: 生成の非決定性。
- 根拠: shisakulab/ai-trade-check README(日本株 30 銘柄、2025-01〜2026-09、外部 AI サービス。公開コードでは再現不可と明記)。
- 効かなくなる条件: 温度 0・固定シードが使えるモデル、または docs ルールを決定的な手順に落とした場合。
- 必要データ: 同一入力での複数回実行ログ。
- 確度: C(1 例、再現不可)。

## 落とし穴・反証・注意

- **「検証用環境」という名前に期待しない**: kabu の 18081 は約定を模擬しない。公式が「取引所側に約定機能があるのでデモは難しい」と説明済み。
- **日足の始値 = 9:00 の価格ではない**: 特別気配で寄りが遅れた日の O は 9:00 以降の板寄せ値。寄成なら約定はするが、寄り前気配で判断したルールの前提(時刻)がずれる。
- **J-Quants の UL/LL は高値・安値ベース**: ストップ寄り・ストップ引けの判定には使えない。O・C と制限値段を自分で比べる。
- **J-Quants Free は 12 週遅延**: 日次の答え合わせには使えない。yfinance は当日終値が取れるが、未確定の末尾バー・1/10 価格・配当未調整・OHLC の微小矛盾が実測されている(quant-jp)。
- **調整済み株価の配当落ち**: 配当落ち日が偽の下落日になる(stock-bot)。O→C は同日内なので影響は小さいが、前日終値を使う特徴量やストップ判定は調整前価格で行う。
- **生存バイアス**: yfinance は上場廃止銘柄を返さない。quant-jp の実測では歪みは −0.40 ポイントと小さく向きも逆だったが、戦略によって変わる。
- **期間をまたぐ制度差**: 2023-06-05(Mid400 呼値)、2024-11-05(15:30 引け・CA)、2027-03-01(STR 呼値)、2027-10-12(ランダムクローズ)。コストと「引け」の定義は日付で切り替える。
- **S株(単元未満株)では同日 O→C はできない可能性**: quant-jp は S株を「翌営業日寄付で執行」として使っている。デイトレの現実性を問うなら 100 株単位が前提で、1 銘柄あたり株価 × 100 円が要る。予測の採点だけならリターン率で足りる。
- **空売り側の現実性は未調査**: 貸借・一般信用の在庫、特別空売り料、空売り価格規制(JPX の該当ページは未読)。売り予測の採点は「買い予測と対称」と仮定しているだけ。
- **ライセンスなしリポジトリ**: quant-jp と kyohah サンプルはコード転載不可。本ノートのコードは自作で、設計上の着想のみ参考にした。
- **moomoo の記載の食い違い**: OpenAPI doc の導入ページは日本株 Quote を ✓、権限ページは Unsupported。デモ取引の初期資金も、ヘルプは日本株 2,000 万円、紹介ページは 100 万米ドルと表記。
- **backtrader の同日決済、LEAN の日本株、nautilus の Bar 分割は推測を含む**。採用しないので深追いしていない。
- **反証として**: stock-bot は方法論を尽くした上で「エッジなし」と結論している。ai-trade-check でも AI の拒否権は成績を下げた。基盤を作ることと予測が当たることは別問題。
- 本ノートの bps 表・寄り遅延の式・推奨コスト設定は自分の計算・提案であり、実測で検証されたものではない。

## このプロジェクトへの提案(MVP で採用するもの、後回しにするもの)

MVP で採用:

1. 採点エンジンは自作(詳細 G)。依存は pandas / numpy のみ。
2. 記録は 1 営業日 1 JSON の追記専用 + ハッシュチェーン + git コミット。予測の締め切りは寄り前(例 8:50)で、`generated_at` と `git_commit` を記録に含める。
3. 採点は 16:30 以降(J-Quants 日足の更新目安)。未確定バーは翌日回し、未処理営業日はまとめて処理するキャッチアップ設計。
4. コストは 3 ケース併記(基準 0 / 片道 0.5 tick / 片道 5bps)。合否は厳格ケースで判定。
5. 不約定ルール: 始値なし・出来高 0・ストップ寄り(買いはストップ高、売りはストップ安)は不約定。引けがストップに張り付いた日は旗を立てて別集計。
6. 統計: 的中率、平均 net(bps)、日単位ブロックのブートストラップ CI、同日の TOPIX 連動 ETF の O→C を引いた超過。試行(ルール・モデル)の通し番号を必ず残す。
7. 事前登録文書(`CRITERIA.md` 相当)を開始前に確定: 欠測上限、手編集 0、最小試行日数、中断条件、「バックテストで勝った結果は証拠にしない」。
8. カレンダーは exchange_calendars の XTKS。レポートは quantstats。
9. 呼値・更新値幅・制限値幅・CA 規則を docs のルール表として持ち、適用開始日つきで版管理する(2027-03-01、2027-10-12 の変更を予告として記載)。
10. docs ルール予測(人間・LLM)とプログラム予測は同じ JSON スキーマで記録し、同じ採点関数にかける。LLM は同一入力で複数回実行してぶれを記録。

後回し:

- nautilus_trader / LEAN / zipline-reloaded: 指値・逆指値・持ち越し・資金配分が必要になった時点で検討。
- vectorbt での照合: 複数日保有の戦略を足したとき。別 venv に隔離。
- 証券 API(kabu、立花デモ): 実弾の I/F 検証段階まで不要。
- 分足・ティック(J-Quants アドオン月 5,500 円)、寄り前気配(BRiSK 等): 特別気配・寄り時刻・日中損切りを扱う段階で。
- moomoo デモ取引: 手動での体感確認用。自動化の対象にしない。
- 空売りの現実性(在庫・規制・特別空売り料)のモデル化。

採用しない:

- backtrader(実質停止)、freqtrade / jesse / hummingbot(暗号資産専用)、kabu 検証用環境をペーパー環境として使うこと。
